# Завдання 13. Чи справді це витік пам'яті (середнє)

У звіті студента написано:

> Програма читає 400 МіБ дрібних записів у список `data`. Після `del data` значення `VmRSS` у `/proc/self/status` майже не зменшилося. Отже, лічильник посилань у Python не працює: це витік пам'яті. Потрібно вимкнути збирач сміття (`gc.disable()`) і звільняти пам'ять вручну.

**Умова.**
- Знайдіть щонайменше три хибні або необґрунтовані твердження у міркуванні.
- Поясніть, що насправді могло відбутися із пам'яттю після `del data`.
- Запропонуйте, як перевірити, чи це справді витік, і назвіть інструмент.

**Обсяг.** 8-12 речень.

---

Відповідь:

Міркування студента містить три хибні твердження: по-перше, лічильник посилань у Python працює ідеально, але del data видаляє лише посилання на список, а не гарантує негайне повернення всієї пам'яті операційній системі; по-друге, рівень VmRSS показує загальний обсяг резидентної пам'яті процесу, яку аллокатор Python міг зберегти у своєму внутрішньому пулі для швидкого виділення надалі; по-третє, вимкнення збирача сміття (gc.disable()) жодним чином не допоможе вивільнити пам'ять з-під простих списків. Насправді після del data пам'ять повернулася до внутрішнього менеджера пам'яті Python (pymalloc), який тримає її зарезервованою для майбутніх потреб процесу, а операційна система її не бачить як вільну через механізм фрагментації. Щоб перевірити, чи є тут справжній витік, слід використовувати спеціалізовані інструменти на кшталт tracemalloc, який показує джерела виділення пам'яті у байтах. Також можна порівняти значення у динаміці за допомогою утиліт моніторингу або повторити операцію багаторазово, спостерігаючи за стабільністю росту споживання пам'яті.
